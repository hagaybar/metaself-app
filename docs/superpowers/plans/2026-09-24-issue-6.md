# The walk behaves like the app (public issue #6) — Implementation Plan

**Goal:** a "nothing happens" finding from an agent walk can be believed without first reproducing
it by hand. Every item below removes one way the harness (`app/src/test/java/com/metaself/app/sim/`
and the shared session driver `ui/ComposeSession.kt`) could make the app look silent when it is not.

**Test code only.** Nothing under `app/src/main` changes; if a seam turns out to be unavoidable it is
named in the commit and in the report. No version bump: nothing ships.

**Branch:** `walk-harness-behaves-like-the-app`. Not pushed.

## Order, and why

Data first, because the screen items are only worth testing against stores that behave.

1. **Ordering and stamping (issue item 3).** One clock for the whole walk, shared by every stand-in,
   so "most recent first" compares like with like. `FakeFoodRepository` stamps `updatedAtMillis` on
   every write the real statements stamp (the three guarded writes, clears, rename via `touch`,
   brand, barcode, hide/unhide, join via `touch`) and orders exactly as `FoodDao` does:
   `observeAll` by `updatedAtMillis DESC, id DESC`; `observeOffered` by the later of that and the
   food's latest logging, then `id DESC`. The latest logging is read from the day's rows when a day
   store is attached (the walk), and is absent otherwise, as a database with no rows. The walk's
   saved meals order the same way (`SavedMealDao.observeOffered`), including the `id DESC` tie.
   *Proved by:* a fake-level test per query — ties broken by id, an edit bringing a food to the top,
   a logging bringing a food to the top of the offered list, a hidden food's stamp, the repair not
   moving a food.
2. **Refusals and what a join moves (issue item 4).** The food stand-in answers the saved-meal
   questions from the saved meals themselves when the walk wires them in: `delete` refuses
   `UsedBySavedMeals`, emptying the per-unit group refuses `NeededBySavedMeals`, `merge` refuses
   `MealsHoldingBoth`, and a join moves past rows, meal components and names as `RoomFoodRepository`
   does. A deleted food detaches its logged rows (`ON DELETE SET NULL`). The existing unit-test
   switches (`usedBySavedMeals`, `refusesToMerge`) keep working for tests with no meals wired.
   *Proved by:* tests that fail today — deleting a food a saved meal holds is refused; emptying the
   units a meal counts in is refused; joining two foods one meal holds is refused; a join keeps the
   meal's part (today the part silently vanishes) and repoints the day's rows.
3. **A press is a touch (issue item 1).** `ComposeSession` presses and holds through Compose's
   touch injection, so hit-testing applies. While a touch-modal window (a menu, a dialog, a sheet) is
   open, only what is in it can be reached; an instruction naming something beneath it is delivered
   as a tap outside that window, which the window answers as a phone does (a menu closes). The "can
   be touched here" list shows only what is reachable.
   *Proved by:* `ComposeSessionTest` — with a menu open, pressing a control behind it does not
   reach it and closes the menu; the list of what can be touched names the menu's items only; a
   control inside the menu still works. And against the day's real More menu in the shell.
4. **Screens keep their state on the back stack (issue item 2).** Every entry on the shell's stack
   keeps its view models and saved state until it is popped, as `NavBackStackEntry` does — not only
   the manager. *Proved by:* on *Add something*, the tab and the search survive opening a food's
   page and coming back; in the manager, ticked foods survive the same; a popped entry comes back
   fresh.
5. **Geometry (issue item 5).** Robolectric renders on a 320 dp canvas with no real font, so
   absolute bounds would be recorded measurements of nothing. The transcript says so in its header,
   and says which window each line was read from (the screen, or a menu/dialog over it) — the one
   spatial fact this harness does know. *Proved by:* a `Transcript` render test.
6. **A committed regression walk.** The corrected cold-start walk from the archive, adapted to
   today's app (foods made on *Type the numbers*, a meal built in the manager, logged from *Add
   something* → the meal → *Log it*), with invented foods and figures, committed as a script plus a
   test that fails on any step that did not happen and checks the meal reached the day.
